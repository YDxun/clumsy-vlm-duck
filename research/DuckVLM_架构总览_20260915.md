# DuckVLM 架构总览 · 2026-09-15

> 分支 `codex/duck-vlm-harness` · 最新提交 `4eb5121` · 单元测试 32 项全绿
> 远程：`/root/microduck_sim`（RoboGo 单卡 5090），服务 8080，无 X5 开发板

## 1. 一句话

让 VLM 每一步只输出**一个离散动作符号**，由本地解释器落到鸭子已有的 ONNX 行走/踢球策略上；
成败由 MuJoCo 真值判定；插件在"感知—推理—动作"链路上提供子目标、探索、对齐、恢复等能力，
并且每个插件都能单独开关做消融。

## 2. 分层架构

```
┌──────────────────────────────────────────────────────────────────────┐
│ L4 浏览器驾驶舱   _dev_cockpit/web/vlm.html  (驾驶舱 + 插件勾选 + 人工接管) │
├──────────────────────────────────────────────────────────────────────┤
│ L3 决策层  DuckVlmLoop (duck_vlm/loop.py)                             │
│    每步：拍照 → 插件改写观测 → VLM 出一个 token → 插件改写 token → 执行   │
│    低延迟层：局面无歧义时插件直接给动作，跳过 ~1s 的模型往返              │
├──────────────────────────────────────────────────────────────────────┤
│ L2 插件层  PluginSuite (duck_vlm/plugins.py)  9 个插件，可独立消融        │
│    proprioception / action_memory / subgoal / affordance / recovery   │
│    search_align / explore / human_takeover / fall_recovery            │
├──────────────────────────────────────────────────────────────────────┤
│ L1 技能层  DuckActionInterpreter (duck_vlm/interpreter.py)            │
│    速度类 token → alpha_walking；头部 token → 直接写头关节；            │
│    技能类 token → LocalKick 状态机 (ball_kick / roulade / happy_hop)   │
├──────────────────────────────────────────────────────────────────────┤
│ L0 仿真/真机  LocalSim (sim_server.py) + 场景包 duck_scenes/            │
│    MuJoCo 50Hz 物理 + ONNX 策略推理；有 X5 板时同一接口走板端            │
└──────────────────────────────────────────────────────────────────────┘
```

## 3. 单步数据流

```
TaskManager(场景 tasks.yaml) ──任务定义──┐
DuckStateSensor(state.py) ──本体+目标可见性┤
                                          ▼
                             VlmObservation (types.py)
                    task / target / 图像 / 状态 / 最近动作 / 插件文本
                                          │
                    PluginSuite.before_decision()  ← 子目标、探索提示、affordance
                                          ▼
                       prompt (prompts/zero_shot.txt | finetuned.txt)
                                          ▼
                       VlmDecisionClient  → 一个动作 token
                                          ▼
                    PluginSuite.resolve_token()  ← 对齐、探索、恢复纠偏
                                          ▼
                    DuckActionInterpreter → 速度指令 / 头关节 / 技能
                                          ▼
                    MuJoCo 推进 → 新状态 → TaskEvaluator 判成败 → 回到第一步
```

## 5. 动作空间（15 个 token）

| 类别 | token | 落地方式 |
| --- | --- | --- |
| 移动 | `FWD` `BACK` `STRAFE_L/R` | 速度指令 → `alpha_walking` |
| 转向 | `TURN_L` `TURN_R` | ±1.5 rad/s（死区外，见 §7.1） |
| 控制 | `STOP` `STAND` | 零速保持 |
| 头部 | `LOOK_DOWN` `HEAD_CENTER` | 直接写 `head_pitch`/`neck_pitch`，**锁存** |
| 技能 | `KICK_L/R` `ROLL` `DANCE` | `LocalKick` 状态机 + 对应 ONNX |
| 终止 | `DONE` | 需真值 evaluator 同意，否则忽略（见 §7.6） |

## 6. 已完成

### 6.1 闭环与评测
- 场景包三套：`duck_workspace_v1` / `duck_home_v1` / `duck_obstacle_v1` 全部接入，
  场景切换后自动重载机器人、任务、metadata。
- 任务成败由场景包 `TaskEvaluator` 用 MuJoCo 真值判定，**不采信模型主观 `DONE`**。
- 过早 `DONE` 会被忽略并继续在原预算内执行（记录 `done_ignored`）。

### 6.2 感知
- 头摄 320x240（`DuckHeadCam`，62° HFOV，固定 20° 俯角），跟随真实头关节。
- **可见性门控**：目标在视锥内且通过 `mj_ray` 遮挡检测，才给出距离/方位/世界坐标；
  否则全部 `None`。即"看不见就不给上帝视角真值"。
- 头摄图上画出目标投影点，并给出在画面中的像素坐标。

### 6.3 动作
- 转向死区标定并修复（`TURN_R` 从空动作变成 -1.02 rad/s）。
- 头部动作：`LOOK_DOWN`（低头 34°，覆盖 0.15~0.45 m）与 `HEAD_CENTER`，锁存到下一步。
- 转向时长按航向误差自适应（<15° 压到 0.45x，<35° 压到 0.70x），避免过冲。

### 6.4 插件
| 插件 | 解决什么 | 状态 |
| --- | --- | --- |
| `proprioception` | 把本体状态写进 prompt | ✅ |
| `action_memory` | 最近动作历史 | ✅ |
| `subgoal` | 目标距离/航向误差 verbalize；按上次可见距离决定是否提示 `LOOK_DOWN` | ✅ |
| `affordance` | 目标距离/方位/可见性 + 图像标注 | ✅ |
| `recovery` | 重复动作与无进展检测、反向纠正 | ✅ |
| `search_align` | 盲区有界扫描（≤6 步单向）；可见时"已朝向就前进" | ✅ |
| `explore` | **门洞优先巡游 + 地板覆盖**，无目标时走向最近开口 | ✅ |
| `human_takeover` | 人工/GUI 直接插入一个动作（GUMI 式数据采集） | ✅ |
| `fall_recovery` | 摔倒后延迟自动复位 | ✅ |

### 6.5 探索（本轮重点）
- `map.py` 从场景 XML 解析墙段 → 门洞（home 实测 1 个，中心 (0,0)，宽 1.5 m，沿 x 通行）。
- `ExplorePlugin` 航点顺序：门洞中心 → 门外 1 m 穿越点 → 覆盖网格（按门前距离排序）。
- 三道闸门：`SKIP_TASKS`（姿态/步态/绕行任务）、目标可见时让位、`SEEN_HOLD_STEPS=8`
  （刚看见就丢失属局部感知问题，不掉头远征）。

### 6.6 低延迟层
- 每步问 VLM 花 ~1.2 s 预算，而走一步只 0.55 s——这才是把时间耗光的元凶。
- 无歧义时插件直接给动作，记录 `source="reactive"` 以便消融。
- 实测 `search_ball_across_rooms` 步数 32 → 63~90。

### 6.7 录制与数据
- **三视角拼接 960x240**：`[鸭头摄 | 第三人称跟随 | 全场俯瞰]`，实时 ~10 fps。
- 逐步另存 `frames/` `frames_track/` `frames_overview/` `frames_dual/`。
- `export_alpaca()` → `llamafactory.json`（图像 + prompt + 动作 token），供 LoRA 微调。
- 人工接管动作一并记录，即 GUMI 式"不需要遥操作设备"的数据采集。

### 6.8 实测成绩（zero_shot + Qwen3-VL，成败=真值）
| 场景 | 任务 | 结果 |
| --- | --- | --- |
| workspace | `walk_to_ball` | ✅ 8 步 |
| workspace | `walk_turn_stop` | ✅ 11 步 |
| home | `search_ball_across_rooms` | ⏳ 三次均穿过门洞进东屋，距球 1.17~1.41 m 后 60 s 预算耗尽 |

## 7. 已定位并修复的问题（作为设计决策记录）

1. **转向死区**：`TURN_R = wz -1.0` 实测仅 -0.011 rad/s（等于空动作），
   而 `-1.5` 有 -1.018 rad/s。这解释了"只有右转失败"。
2. **语义实体漏 `people`**：`resolve_body` 只遍历 objects/zones，`owner`/`stranger`
   永远解析失败，鸭子只会原地转。
3. **场景出生点写死**：`LocalSim.reset()` 对所有场景都重置到 workspace 原点与 (0.9,0)，
   Home"跨房间"其实不跨房间。改用场景 keyframe。
4. **`record=False` 打崩服务**：`save_image()` 在 recorder 未激活时抛异常。
5. **探索插件越权**：抢走 `walk_turn_stop`；刚丢目标就远征；看见目标把巡游进度清零
   （导致 1.22 m → 4.10 m 倒退）；贪心选最近航点导致只在出发房间打转。
6. **真值泄漏**：不可见时也给 distance/bearing，使早期"Home 成功"结论不成立，已撤回。

## 8. 卡点与待优化

### P0 · 决定能否跑通 Home 任务
- **60 s 预算 vs 4.4 m 路程**：跨房间后到球还需 ~1.2 m，
  按当前每步净位移 ~0.1 m 与决策开销，恰好差一口气。
  可选：进新房间后先"扫视 + LOOK_DOWN"就近搜索；把最终接近也放进低延迟层；
  或与场景包作者确认放宽 `max_duration_s`。
- **进屋后的搜索策略缺失**：目前进新区域后仍按全局覆盖网格走，缺少
  "以最后目击点为中心做局部搜索"的行为。

### P1 · 能力缺口
- **无深度感知**：距离来自"可见时的真值"，真机迁移必须补
  （MuJoCo depth 渲染 / 双目 / 单目深度）。
- **`kick_ball_to_zone` / `retrieve_ball` 缺站位规划**：需要显式站位点
  （球位 + 朝绿区反方向偏移），把"绕到球后方"变成子目标。
- **0.10 m 以内仍是视觉盲区**：`LOOK_DOWN` 覆盖到 0.15 m，更近需要第二档低头。
- **绕障/绕人无路径规划**：`avoid_obstacle_*` / `orbit_*` 目前被探索插件豁免，
  需要绕行航点。

### P2 · 工程与验证
- **微调链路未跑通**：`finetuned` 模式的 OpenAI 兼容协议与 `ft_base_url`
  （默认 `http://127.0.0.1:8000/v1`）已就位，`export_alpaca` 也能出数据集，
  但**尚未真正训练 LoRA、也未部署 vLLM**。
- **消融实验未系统化**：插件已可单独开关，但没有批量跑数出对比表。
- **无自动回归**：32 个单测覆盖插件与录制，但没有"跑 scene 任务判成败"的 CI 级回归。
- **demo 资产体积**：三个 GIF 合计约 14 MB。

## 10. 复现方式

```bash
# 切场景
printf 'duck_home_v1\n' > /root/microduck_sim/.duck_scene_id
cd /root/microduck_sim && python3 service.py restart

# 跑一个任务（zero_shot）
curl -X POST http://127.0.0.1:8080/api/vlm/control \
  -H 'Content-Type: application/json' \
  -d '{"action":"start","task":"search_ball_across_rooms","target":"ball",
       "mode":"zero_shot","record":true,"auto_run":true,
       "config":{"max_steps":90}}'

# 单元测试
python -m pytest duck_vlm/tests/test_core.py -q     # 32 passed
```
