# 场景包人体仿真需求提示词 · 2026-09-15

> 本文是交给仿真助手的需求说明，可直接转发。
> 目的：让 `duck_scenes` 验证场景包里的"人"变成**会走、会停、会转身、会做手势**的可信人体，
> 从而让 `follow_owner` / `come_to_owner` / `orbit_stranger` 真正测出能力。

---

## 0. 先看清现状（避免重复造轮子）

仓库里目前有**两套互不相通**的"人"：

### A. `duck_play/` 里已有一套不错的人物子系统（2026-09-09 完成，commit `85d3e9a`）

- `duck_play/scenes/gen_person_scene.py`：生成 `scene_person.xml`，
  人是 **`mocap="true"` 的运动学人体**，含腿/躯干/头/身份标签，`contype=conaffinity=0`
  （不与鸭子做物理碰撞），owner 红衫、stranger 蓝衫。
- `duck_play/behavior/pose.py` · `PoseManager`：**双臂关节化**（上臂+前臂两段 mocap 体），
  5 种手势 `idle / right_fwd / left_fwd / both_fwd / both_side`，
  并有 shoulder/elbow/wrist **marker 体提供精确 GT 关键点**。
- `duck_play/behavior/person_follow.py` · `PersonFollowController`：状态机
  `SUMMON / FOLLOW / ORBIT / SEARCH`。
- `duck_play/behavior/gesture_map.py`：手势 → 鸭子动作，要求稳定 0.6 s 才触发。
- `duck_play/vision/pose_vision.py`：`PoseOnnx` + `classify_gesture_2d`，
  即**基于真实视觉**（不是 GT）的手势识别。
- `duck_play/vision/gen_pose_dataset.py`、`benchmark_gesture.py`、`gen_gesture_eval.py`：
  合成数据生成 + 评测工具。
- 训练好的模型：`research/artifacts/pose-gesture-v8/pose_model.onnx`（YOLO11m-pose@480）。
- 演示视频：`research/demo_videos/person_l1.mp4`、`gesture_owner.mp4`、`gesture_owner_wide.mp4`。

### B. `duck_scenes/` 验证场景包里的"人"（**这是问题所在**）

`duck_scenes/scenes/duck_home_v1/scene.xml`：

```xml
<body name="person_owner" pos="1.65 0.55 0.45">
  <geom name="geom_owner" type="capsule" size="0.12 0.33" rgba="0.9 0.12 0.12 1"/>
</body>
```

**没有 `freejoint`、没有任何 `joint`、也不是 mocap —— 就是一根立在地上的红色药丸，完全不能动。**
`person_stranger` 同理（蓝色）。另外两个场景包里根本没有"人"。

后果：

| 任务 | 现在的实际含义 |
| --- | --- |
| `come_to_owner` | 走到静止红药丸 0.5 m 内 |
| `follow_owner` | 对着**静止杆子**保持 0.5~1.0 m 连续 3 s（近乎平凡，测不出跟随能力） |
| `orbit_stranger` | 绕到静止蓝药丸的侧后方 |

### 已有的升级规划（也不用重写）

- `research/human_sim_vision_plan.md`
- `research/duck_person_sim2real_dataset_design.md`
  已给出 L0 胶囊 → L1 关节化低模人形 → L2 多套数字人资产 → L3 真人动作重定向 的路线，

## 1. 本次任务（一句话）

**把 A 里已有的 mocap 运动学人体，移植进 B 的验证场景包，并让它可以按脚本走、停、转身、做手势；
同时按已有规划把外观从"药丸"提升到"可被 VLM 认出是人"的程度。**

不要重新设计一套人体，优先复用 `PoseManager` 与已训练模型。

---

## 2. 硬性要求（不满足就无法接入现有评测）

1. **body 名字不能改**：必须仍然叫 `person_owner` / `person_stranger`。
   评测器 `duck_scenes/validation_core.py` 用 `<body name>` 定位目标
   （`distance_xy_le` / `distance_xy_range` / `relative_bearing_range` 等条件都按名字取 `xpos`）。
2. **`metadata.yaml` 的 `people` 段要保留并扩展**，至少包含：
   ```yaml
   people:
   - id: owner
     body: person_owner
     radius_m: 0.12
     height_m: 0.9
     center_z_m: 0.45
     semantic_labels: [owner, 主人]
     collision: true
     # 新增：
     controller: owner_walk          # 控制器实例名
     path: [[1.65,0.55],[0.60,0.55],[0.60,-1.20]]   # 世界坐标航点
     speed_mps: 0.55
     events:
       - {t: 8.0, action: gesture, name: right_fwd}
       - {t: 20.0, action: face, target: duck}
   ```
   现有 `duck_vlm/scenes.py` 会遍历 `people` 做语义解析（`owner` / `主人` → `person_owner`），
   字段只做新增、不要破坏已有键名。
3. **body 原点必须保持在人体中部（约 z=0.45 m）**。DuckVLM 用
   `duck_vlm/state.py` 把 body 原点投影到头摄画面判断可见性；若原点放到脚下或头顶，
   可见性判定会失真。
4. **与鸭子的碰撞要可控**：参考 A 的做法（`contype/conaffinity=0`）避免人体把鸭子顶飞；
   若必须保留碰撞，请用独立的低刚度接触参数，并在验收里给出"最小间距 ≥0.15 m 且无异常接触力"的证据。
5. **不能改动现有 6 个任务的成功/失败条件**。要测新行为请**新增任务**。
6. **门洞几何与家具布局保持不变**（home 场景的门洞在 (0,0)，宽 1.5 m，沿 x 通行，
   `duck_vlm/map.py` 依赖它做探索，改了会让探索航点失效）。

---

## 3. 行为要求

必须支持（可脚本配置）：

| 行为 | 说明 |
| --- | --- |
| idle | 站立，可选轻微呼吸/摆动 |
| walk | 沿给定航点列表以指定速度行走，到点即停 |
| stop / resume | 事件触发 |
| turn_to | 转向指定目标（鸭子或某点），转身平滑 |
| face_duck | 鸭子靠近时转身面对它 |
| gesture | 复用 A 的 5 种手势（idle/right_fwd/left_fwd/both_fwd/both_side） |
| react_back_away | 鸭子进入 0.35 m 内时后退一步（测"安全距离"） |
| hand_over | （可选）手持物体递出，供"接物"类任务 |

运动方式建议：**继续用 `mocap="true"` 的运动学驱动**（`data.mocap_pos/quat`），
不要做物理仿真的人形机器人。理由：稳定（不会摔、不会穿模、不会和鸭子碰撞爆炸）、
便宜（不占物理步进）、可控（路径/速度/时刻可精确指定），且 `d.xpos` 照常更新，
现有评测器完全兼容。

## 4. 外观要求（分级验收）

- **必须达到**：鸭子头摄（320x240，水平 FOV 62°，安装俯角 20°）在 **2 m 处**拍到的"人"
  要能被 VLM（Qwen3-VL 等）认出是"person/人"，而不是"柱子/标记"。
  参考量：2 m 处 0.9 m 高的人约占画面高度 100 px 以上。
- **最低结构**：头（含面部色块/五官暗示）+ 躯干 + 两条腿 + 两条**可动手臂**（肩/肘/腕三段感）。
- **身份可区分**：owner 与 stranger 至少在两个维度上不同（例如：上衣颜色 + 身高，或 + 一个胸前标志物），
  便于 VLM 与检测器区分。
- **建议（若成本允许）**：按 `human_sim_vision_plan.md` 的 A 方案引入带贴图的低模人形网格，
  使 COCO person 检测器/RTMPose 在仿真图上也能工作，为 Sim2Real 打底。

---

## 5. 验收标准（可量化，请逐条给出证据）

1. MuJoCo 加载三套场景 XML 无错（`validate.py` 通过），原有 6 个任务的成功/失败条件行为不变。
2. 2000 步物理稳定；人体不穿地、不抖动（位置抖动 < 1 cm/step）。
3. 沿 3 m 路径行走：实测平均速度误差 ≤ ±10% 设定值；到达航点误差 ≤ 0.1 m。
4. 转身：从面向 A 转到面向 B，最终朝向误差 ≤ 10°。
5. 手势：5 种手势各自可稳定保持 ≥1 s；用 A 的 `PoseOnnx` 在鸭子头摄上识别，
   任务级手势识别准确率 ≥ 90%（给出混淆矩阵）。
6. 可见性：`DuckStateSensor` 在距离 ≤ 2 m、人在视锥内时判定 `visible=True`；
   隔墙时 `visible=False`（遮挡射线仍生效）。
7. 与鸭子最小间距 ≥ 0.15 m，无异常接触力（给出接触力峰值）。
8. 渲染开销：三视角（鸭头摄 + 第三人称 + 全场俯瞰）同时渲染时，单帧耗时增加 ≤ 30%。
9. 提供 3 段视频：wide 视角跟随 + 鸭头摄 + 三视角拼接（沿用现有
   `frames_dual_live` 的 960x240 布局）。

## 6. 交付物

1. 三套场景的 `scene.xml` 更新（或由脚本生成，须可复现）。
2. `metadata.yaml` 的 `people` 扩展段（见 §2.2）。
3. `PersonController` 模块：API `reset()` / `step(dt)` / `set_path()` / `trigger(event)`，
   放在 `duck_vlm/` 或 `duck_play/behavior/` 下均可，须能被 `sim_server.local_step()` 每步调用。
4. 场景与行为的独立验证脚本（对应 §5 每条标准，输出 PASS/FAIL 表）。
5. 建议新增的任务定义（写入 `tasks.yaml`）：
   - `follow_moving_owner`：主人沿路径走动，鸭子保持 0.5~1.0 m 且连续 5 s → 真正的跟随
   - `greet_and_approach`：主人挥手（`right_fwd`）后再靠近，考"先识别意图再行动"
   - `avoid_walking_person`：迎面走来时鸭子不碰撞（最小间距 ≥0.15 m）
   - `owner_handover`（可选）：主人递物，鸭子靠近并停住
6. 一段 README 说明如何切到新场景、如何跑新任务。
