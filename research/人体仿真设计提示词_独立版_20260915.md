## 1. ⚠️ 第一决策项：鸭子头摄其实看不到人的上半身（实测数据）

这是本次设计的**最重要前提**，必须先用它来定人体尺寸与"身份信息放在哪"。

实测（`duck_workspace_v1`，头摄模型 `duck_play/perception/camera.py`）：

| 项 | 实测值 |
| --- | --- |
| 相机原点高度 | **z = 0.253 m** |
| 水平 FOV / 垂直 FOV | 62° / **48.5°** |
| 光轴俯仰 | **下俯 20°** |
| **画面上边缘** | **地平线以下 4.3°**（连水平方向都看不到） |

由此得出"站在正前方的人，哪些高度会被看到"：

| 水平距离 | 可见 z 窗口 | 含义 |
| --- | --- | --- |
| 0.5 m | 0.00 ~ 0.29 m | 只有脚/脚踝 |
| 1.0 m | 0.00 ~ 0.33 m | 只有小腿 |
| 2.0 m | 0.00 ~ 0.40 m | 小腿到膝盖 |
| 3.0 m | 0.00 ~ 0.48 m | 膝盖附近 |
| 4.5 m | 0.00 ~ 0.58 m | 大腿下半 |

**即使把真人做成 1.7 m，鸭子也只能看到他的小腿以下。**

请按以下**方案 A（推荐）**执行，方案 B 作为备选：

- **方案 A（推荐，改相机而不是改人）**：把头摄"静止姿态"的额外下俯从 20° 改为 **0°（平视）**，
  把"看地面/看球"的能力完全交给已有的 `LOOK_DOWN` 头关节动作。
  改完后 2 m 处可见 z 窗口约 **-0.65 ~ +1.15 m**，3 m 处约 **-1.10 ~ +1.60 m**，
  1.5~1.7 m 高的人才能被完整看到。
  > 影响面：球/踢球类任务在静止姿态下会看不到地面目标，必须靠 `LOOK_DOWN` 补偿；
  > 请在验收里专门测一次 `walk_to_ball` 与 `kick_ball_to_zone` 不受影响。
- **方案 B（不改相机）**：接受"只看到小腿"，则**身份信息必须全部放在 0.30~0.60 m 高度带内**：
  裤腿颜色、鞋子颜色/形状、小腿上的色带或徽章。这种方式无法体现面部与手势，视觉价值低。

**无论选哪个方案，请在人体的 0.30 m / 0.50 m / 0.90 m 三个高度各放一个命名锚点体**（见 §6.1），
让感知层能选择"看得到哪个就报哪个"，而不是只依赖一个 body 原点。

## 2. 尺度与比例：先统一世界观（第二决策项）

当前场景包的尺度是**自相矛盾的**，请一并处理并说明你的选择：

| 物体 | 现状尺寸 | 问题 |
| --- | --- | --- |
| 鸭子总高 | 0.25 m | 约等于真实 microduck，合理 |
| 房间地板 | 6.0 x 5.0 m | 真人房间尺度 |
| 墙高 | **0.25 m** | 只有鸭子那么高，真人房间里应是 2.4~2.6 m |
| 沙发坐垫高 / 桌面高 | **0.10 / 0.08 m** | 只到人的脚踝，真人尺度应是 0.40 / 0.72 m |
| 现有 "owner" 身高 | **0.90 m** | 与鸭子比只有 3.6:1（真人:鸭子 应约 6.8:1） |
| 门洞净宽 | 1.4 m | 真人尺度合理 |

请选一个并保持一致（推荐第一种）：

- **推荐 · 真实房间尺度**：人 **1.70 m**，墙 **2.50 m**，沙发坐垫 **0.40 m**，桌面 **0.72 m**。
  语义 = "鸭子是房间里的一个小玩具机器人"，这也是 microduck 最真实的用途，
  对后面的 Sim2Real 最有价值。
  > 抬高墙体要确认不影响 `duck_vlm/map.py`：它只用墙的 x/y 位置做门洞提取，不看高度，因此安全。
- **备选 · 鸭子尺度微缩世界**：人缩到 0.45~0.5 m（相对鸭子的比例约 1.8~2.0），
  墙保持 0.25 m、家具保持现状。此时"人"更接近玩偶而非真人，视觉识别价值有限。

**不要**只改人、不动其他物体——那会得到"一个人站在膝盖高墙、脚踝高沙发旁"的怪异画面。
若你认为两者都不可行，请给出你的方案与数据依据。

## 3. 身体结构与关节

### 3.1 骨架层级（推荐，身高 1.70 m）

```
world
└── person_root            (mocap 体，位置 + 偏航；所有部件的父节点)
    ├── pelvis              hip 0.92 m
    │   ├── leg_L  → knee_L → ankle_L → foot_L
    │   └── leg_R  → knee_R → ankle_R → foot_R
    ├── torso               shoulder 1.44 m
    │   ├── neck → head     头顶 1.70 m
    │   ├── shoulder_L → elbow_L → wrist_L → hand_L
    │   └── shoulder_R → elbow_R → wrist_R → hand_R
    └── anchors: anchor_low(0.30m) / anchor_mid(0.50m) / anchor_core(0.90m)
```

### 3.2 关节表（可选两种驱动，见 §3.3）

| 关节 | 自由度 | 轴 | 范围 | 备注 |
| --- | --- | --- | --- | --- |
| root（骨盆） | 3 平移 + 偏航 | xyz / z | 地板范围 | 由路径驱动 |
| root 俯仰/滚转 | 2（可选） | x / y | ±5° | 走路轻微起伏 |
| spine | 1（可选） | y | -10° ~ +10° | 前倾 |
| neck | 2 | z / y | ±60° / ±20° | 转头 |
| head | 1 | z | ±45° | `face(duck)` 用 |
| shoulder_L/R | 2 | y / z | -170°~+60° / ±45° | 抬臂、挥手 |
| elbow_L/R | 1 | - | 0 ~ 145° | 屈肘 |
| wrist_L/R | 1（可选） | - | ±60° | 递物/手势 |
| hip_L/R | 2 | y / x | -45°~+45° / ±20° | 迈步 |
| knee_L/R | 1 | - | 0 ~ 120° | 迈步/下蹲 |
| ankle_L/R | 1 | - | ±30° | 落脚 |

合计：**必需 20 个自由度**（root 4 + neck2 + head1 + 双肩4 + 双肘2 + 双髋4 + 双膝2 + 双踝2 = 21，可按需裁剪到 20）。

### 3.3 驱动方式（重要建议）

**请用"运动学/mocap 驱动"，不要做物理仿真的人形机器人。** 三种方式对比：

| 方式 | 稳定性 | 成本 | 可控性 | 建议 |
| --- | --- | --- | --- | --- |
| **A · mocap 运动学体**（`<body mocap="true">`，每步写 `data.mocap_pos/quat`） | 不会摔、不穿模、不与鸭子碰撞爆炸 | 不占物理步进 | 路径/速度/时刻可精确指定 | ✅ **推荐** |
| B · 铰链 + position actuator | 中等，需要调 PID，可能抖 | 占物理步进 | 尚可 | 备选 |
| C · 完整物理人形 | 容易摔，调参成本高 | 高 | 差 | ❌ 不建议 |

用 A 时 `d.xpos[body]` 照常更新，现有评测器完全兼容。所有部件设 `contype=0 conaffinity=0`
（不与鸭子做物理碰撞），把"碰撞/避让"做成**逻辑判定**而不是物理接触。

## 5. 动画与行为

### 5.1 状态机

```
IDLE ──(path 非空)──▶ WALK ──(到达航点)──▶ IDLE
  │                     │
  │                     └─(事件)─▶ GESTURE / TURN_TO / FACE_DUCK
  └─(事件)─▶ SIT ──▶ STAND_UP ──▶ IDLE
任意状态 ──(鸭子在 0.35 m 内)──▶ BACK_AWAY ──(距离恢复)──▶ 回到之前状态
```

### 5.2 行为要求

| 行为 | 说明 | 关键参数 |
| --- | --- | --- |
| `idle` | 站立，可加 ±1 cm 呼吸起伏、±2° 躯干摆动 | `idle_breath_hz=0.25` |
| `walk` | 沿航点列表行走，步态 = 双腿交替摆动 + 躯干上下起伏 | 见 §5.3 |
| `turn_to(yaw)` | 平滑转向，角速度受限 | `turn_rate_max=90°/s` |
| `face_duck` | 头 + 躯干转向鸭子（头先动，躯干跟随） | 朝向误差 ≤10° |
| `gesture(name)` | 至少 4 种：`wave`（挥手）、`point`（指物）、`raise_right`（右手上举）、`both_side`（T 字平举） | 每个手势保持 ≥1.5 s |
| `sit` / `stand_up` | 可选，骨盆下降 0.45 m，膝盖屈曲 | - |
| `back_away` | 鸭子 <0.35 m 时后撤 0.4 m | 后撤速度 0.4 m/s |
| `hand_over` | 可选，前臂前伸至前方 0.35 m | 保持 2 s |

### 5.3 步态参数（运动学脚本即可，不需要真实动力学）

- 步幅 0.55 m，步频 1.8 步/秒 → 速度约 **0.9 m/s**（可调 0.2~1.2 m/s）
- 髋关节摆动 ±25°，膝关节 0~45°，踝关节 ±12°
- 骨盆上下起伏 ±0.025 m，左右摆 ±0.02 m
- 双臂反向自然摆动 ±20°
- 行走时脚**不得穿透地面**（最低点 z ≥ 0）

## 6. 与当前项目的集成契约（必须满足，否则接不进去）

### 6.1 body 命名（**不能改**）

评测器 `duck_scenes/validation_core.py` 通过 `<body name>` 取 `xpos` 来算距离/方位，

必须存在以下命名（`owner` / `stranger` 为实例名）：

| 用途 | 名字 |
| --- | --- |
| 主人根体 | `person_owner` |
| 陌生人根体 | `person_stranger` |
| 低处锚点（0.30 m） | `person_owner_anchor_low` / `person_stranger_anchor_low` |
| 中部锚点（0.50 m） | `person_owner_anchor_mid` / `person_stranger_anchor_mid` |
| 核心锚点（0.90 m） | `person_owner_anchor_core` / `person_stranger_anchor_core` |

| 双手 | `person_owner_hand_L/R` 等 |
| 双脚 | `person_owner_foot_L/R` 等 |

`person_owner` 的 body 原点请放在**骨盆（约 0.92 m）**，不要放在脚下。
评测距离用骨盆是对的（人不是脚印）。

### 6.2 `metadata.yaml` 扩展

现有字段不要删，按下面新增：


### 6.3 控制器接口

需要一个模块（放在 `duck_vlm/` 或新目录均可），供 `sim_server.local_step()` 每步调用：

```python
class PersonController:
    def reset(self) -> None: ...
    def step(self, dt: float, sim_time: float, duck_xy: tuple[float, float]) -> None: ...
    def set_path(self, waypoints: list[tuple[float, float]], speed_mps: float) -> None: ...
    def trigger(self, action: str, **kwargs) -> None: ...   # gesture / face_duck / sit ...
    def state(self) -> dict: ...    # 当前行为、位置、朝向，供日志与 prompt
```

要求：`step()` 内**不得**做文件 IO、不得联网、单步耗时 < 1 ms。

### 6.4 不能破坏的东西

- 现有 6 个任务的成功/失败条件**不许改**；要测新行为请**新增任务**。
- `duck_home_v1` 的门洞几何必须保持：中心 **(0, 0)**、净宽 **1.4~1.5 m**、沿 **x** 通行
  （`duck_vlm/map.py` 靠它算探索航点）。
- `duck_vlm/tests/test_core.py` 现有 **32 项测试**必须继续全绿。

## 8. 验收标准（逐条给证据）

1. 三套场景 XML 加载通过；`duck_scenes/scenes/*/validate.py` 复跑通过，`validation.json` 附上。
2. 2000 步物理稳定；人体不穿地、不抖动（位置抖动 < 1 cm/step、最低点 z ≥ 0）。
3. **可见性（最关键）**：把人在 (x=+d, y=0) 站立摆放，
   `DuckStateSensor` 在 **d = 1.0 / 2.0 / 3.0 m** 处的判定与 §1 表格一致；
   并单独给出一张"2 m 处头摄截图"，人工确认能看出是**人**（不是柱子）。
   若采用方案 A，请额外给出改俯角后 1.5 m 与 2.5 m 处的截图。
4. 沿 3 m 直线路径行走：实测平均速度误差 ≤ ±10%；到达航点误差 ≤ 0.1 m。
5. `face_duck`：最终朝向误差 ≤ 10°；`turn_to` 角速度不超过设定上限。
6. 4 种手势各保持 ≥1.5 s；用鸭子头摄截图证明每种手势在画面上可区分。
7. 与鸭子最小间距可逻辑保证 ≥0.15 m，不产生异常接触力（给接触力峰值，应为 0）。
8. 渲染开销：三视角（鸭头摄 320x240 + 第三人称 640x480 + 全场俯瞰 640x360）
   同时渲染时，单帧总耗时增加 ≤ 30%（给出改前/改后 ms）。
9. 现有 32 项单测全绿；`walk_to_ball` 与 `walk_turn_stop` 仍能成功（若采用方案 A，
   需特别验证 `walk_to_ball` 不受"静止姿态改平视"影响）。
10. 提供 3 段视频：wide 跟随视角、鸭头摄、三视角拼接（960x240 卡片布局：
